# PRD 模板

> **只写 What，不写 How。** 验收标准写用户能感知的行为。

---

## PRD · <标题>

**Issue**: #<需求单号>
**优先级**: `priority/pX`
**类型**: `type/feature`
**状态**: `status/prd-drafting` → `status/prd-review` → `status/prd-approved`

### 一、背景

<为什么这事值得做，用户目前遇到啥困扰。1-3 段说清。>

### 二、目标用户 & 场景

<谁会用、什么时候会用、怎么用。>

### 三、用户价值

<解决他什么问题、感受到什么改善。>

### 四、验收标准

- [ ] <用户能感知的行为 1，例：3 秒内看到成功提示>
- [ ] <用户能感知的行为 2>
- [ ] <用户能感知的行为 3>
- [ ] <边缘情况处理，例：网络断了会有明确错误提示>

### 五、不做的事

<明确圈出不在本次范围内的，避免边界模糊。>

### 六、相关证据

- 反馈来源：<群消息链接 / issue 链接>
- 类似 issue：<链接>
- 相关设计文档：<链接>

## 禁写清单（Review 会打回的）

- ❌ "用 Redis 缓存 X 秒"
- ❌ "加一张表存 XX"
- ❌ 代码块 / 内部字段名
- ❌ "接口返回 200"（应改成"用户看到成功提示"）
- ❌ "入库成功"（应改成"用户能在列表看到新增的记录"）

## 该写清单（Review 想看到的）

- ✅ 用户感知的具体行为（时间/文案/交互）
- ✅ 明确的验收边界（边缘情况怎么处理）
- ✅ 反馈溯源（谁在哪说的）
- ✅ 不做的事（避免范围蔓延）
